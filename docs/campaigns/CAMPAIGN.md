`workflowComplete` و `sellable` دو چیز جدا هستند و هیچ‌کدام جای دیگری را نمی‌گیرد.

           → INTEGRATION_VERIFIED → DEVICE_VERIFIED
           → PILOT_VERIFIED → SELLABLE

| `INTEGRATION_VERIFIED` | API، PostgreSQL، حسابداری، Sync       | `*.pg.test.ts`                               |
| `DEVICE_VERIFIED`      | Windows، Android، Browser             | اجرای ثبت‌شده                                |

## ۶. سیاست شاهد

**شاهد است:** خروجی یک فرمان با کد خروج ۰ · یک `*.pg.test.ts` که روی PostgreSQL واقعی نوشته و
خوانده · یک تست HTTP با `buildServer()` + `app.inject` · یک journey مرورگر روی درخت commit‌شده.

**شاهد نیست:** تست واحد سبز به‌تنهایی · grep یک نماد در سورس · ادعای سند · وجود فایل بدون اجرا ·
اجرای محلی روی worktree کثیف · اعداد حافظه.

**قاعده‌ی منفی:** هر قابلیت باید یک تست داشته باشد که **بدون** پیاده‌سازی قرمز شود. اگر برگرداندن
اصلاح، تست را قرمز نمی‌کند، آن تست شاهد نیست.

## ۷. ضد‌هدف‌ها (چیزهایی که این کمپین نمی‌کند)

1. **موتور مستقل برای صنف.** هیچ بسته‌ای «موتور طلا۲» یا «موتور داروخانه» نمی‌سازد.
2. **تغییر وضعیت ماتریس بدون شاهد.** `partial → available` فقط با لنگر کد + تست اجراشده.
3. **ادعای آفلاین روی موتور بدون Local Engine.**
4. **«فروش‌پذیر» بدون PG و مرورگر روی درخت تمیز.**
5. **پرکردن عدد با فرض.** مقدار ناشناخته `null` می‌ماند و «قابل محاسبه نیست» نمایش داده می‌شود.
6. **ویرایش دستی سند تولیدی.** هر سه سند `docs/campaigns/` از مولد می‌آیند.
