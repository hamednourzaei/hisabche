# کمپین تکمیل اصناف — فهرست و روش اجرا

این پوشه پاسخ یک سؤال است: **برای رساندن هر صنف حسابچه به محصول قابل فروش، دقیقاً چه کاری روی
کدام موتور لازم است — و چطور ثابت می‌کنیم انجام شده؟**

پاسخ به‌صورت ۲۶ «بسته‌ی کاری» روی ۲۰ موتور مشترک نوشته شده، نه ۶۷ موتور موازی.

---

## ۱. ترتیب خواندن

|   # | فایل                           | چه چیزی می‌گوید                                             | تولیدشده؟ |
| --: | ------------------------------ | ----------------------------------------------------------- | --------- |
|   ۱ | `CAMPAIGN.md`                  | چرا، با چه فازهایی، با چه قرارداد تولیدی، با چه سیاست شاهدی | دستی      |
|   ۲ | `WORK-PACKAGES.md`             | ۲۶ بسته: هر کدام چه قابلیتی را با چه معیار خروجی می‌بندد    | دستی      |
|   ۳ | `ENGINE-WIRING-STATUS.md`      | ۲۰ موتور و پنج لایه‌ی سیم‌کشی                               | **مولد**  |
|   ۴ | `CAPABILITY-RECONCILIATION.md` | ۳۸ قابلیت: ماتریس ↔ موتور ↔ محدودیت ↔ لنگر کد               | **مولد**  |
|   ۵ | `INDUSTRY-MATRIX.md`           | ۶۷ صنف: وضعیت، موانع، بسته، فاز                             | **مولد**  |
|   ۶ | `COMPETITOR-RESEARCH.md`       | انتظار بازار و ۲۰ الزام (R-01…R-20) با منبع                 | دستی      |

**قاعده:** فایل‌های «مولد» را دستی ویرایش نکنید. اگر عددی اشتباه است، ورودی یا مولد را درست کنید و
دوباره اجرا کنید.

## ۲. بازتولید اعداد

```bash
# سه سند اندازه‌گیری (بدون نوشتن چیزی، فقط بررسی انحراف؛ خروج ۱ اگر کهنه باشد)
node scripts/industry/campaign-status.mjs --check

# نوشتن مجدد
node scripts/industry/campaign-status.mjs
```

هر سه سند از پنج ورودی خوانده می‌شوند و هیچ عددی در متن دستی تایپ نشده است:

| ورودی                                                 | چه چیزی می‌دهد                                        |
| ----------------------------------------------------- | ----------------------------------------------------- |
| `docs/architecture/universal-core/ENGINE-WIRING.csv`  | ۲۰ ردیف موتور + ۳۸ ردیف قابلیت، پنج لایه و کد محدودیت |
| `docs/industries/SHARED-CAPABILITY-MATRIX.md`         | وضعیت اعلامی ۳۸ قابلیت محصول                          |
| `docs/industries/INDUSTRY-REGISTRY.md`                | ۶۷ صنف و قابلیت‌های تخصیص‌یافته                       |
| `docs/architecture/industry/sellable-industries.json` | وضعیت اندازه‌گیری‌شده‌ی ۱۰ معیار                      |
| `scripts/industry/coverage-data.mjs`                  | لنگر کد و فایل تست هر قابلیت                          |

زنجیره‌ی بالادست (اگر رجیستری عوض شد، اول این‌ها):

```bash
node scripts/capability/wiring-matrix.mjs            # ENGINE-WIRING.csv را از کد می‌سازد
node scripts/industry/generate-industry-registry.mjs # INDUSTRY-REGISTRY.md
node scripts/industry/generate-coverage-table.mjs    # جدول شاهد قابلیت‌ها
```

## ۴. آنچه این پوشه اثبات نمی‌کند

1. **هیچ تستی اجرا نشد** برای تولید این اسناد؛ اعداد از فایل‌های موجود و اجراهای قبلی خوانده شده‌اند.
2. **هیچ شاهد PostgreSQL یا مرورگری** در این دور ساخته نشد؛ علت: PostgreSQL محلی نصب نیست.
3. **هیچ مهاجرت، کد محصول، سرویس یا تستی** در این دور تغییر نکرد؛ خروجی فقط سند + یک مولد
   خواندنی است.
4. «لنگر کد سالم» یعنی فایل و نماد وجود دارند، نه اینکه گردش کاربر کامل است.
5. اعداد صنوف از رجیستری می‌آیند؛ اگر رجیستری کم‌انتساب باشد (هست)، این اسناد هم کم‌برآورد می‌کنند.
   `WORK-PACKAGES.md` بخش WP-26 این را به‌عنوان اولین کار باز می‌کند.

## ۵. قدم بعدی

1. `CAMPAIGN.md` بخش ۳ را بخوانید و فاز C0 را تأیید کنید.
2. `node scripts/industry/campaign-status.mjs --check` را در CI بگذارید تا انحراف رجیستری قرمز شود.
3. WP-26 (اصلاح رجیستری) را اجرا کنید؛ بدون آن، هر عدد بعدی تحریف‌شده است.
4. برای C5، PostgreSQL محلی را فراهم کنید؛ تا آن زمان هیچ صنفی به `SELLABLE` نمی‌رسد.
