## 2. Fifty Advantages & Disadvantages — Judged for Hisabche

### Advantages (A1–A25)

| #   | Claim                                                    | Judgment                  | Reason                                                                                                                                              |
| --- | -------------------------------------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | Smaller first install for a single-trade shop            | **APPLIES**               | When `packs.installer=core` and `packs.delivery=on`, unused trade chunk groups are omitted from the initial installer.                              |
| A2  | Less storage on low-end Android phones                   | **APPLIES**               | Only `core` + selected trade packs are stored in the pack store once delivery is enabled.                                                           |
| A3  | Faster cold start (only core parsed)                     | **APPLIES**               | Removing `singleFile` (E1/E2), adding `sideEffects` + deep imports (E4), and lazy pack chunk groups cut cold-start JS parse immediately in Stage 1. |
| A4  | Lower memory (unused trade screens not parsed)           | **APPLIES**               | Unvisited trade chunks stay unparsed in V8/WebView memory.                                                                                          |
| A5  | Fewer bytes on paid mobile data                          | **APPLIES**               | Stage 1 + Stage 2 (locale/entity sync scoping) + Stage 3 (content-addressed packs) reduce install, update, and sync bandwidth.                      |
| A6  | Smaller update when one pack changes                     | **APPLIES**               | Content-addressed chunk filenames preserve unchanged pack hashes across releases.                                                                   |
| A7  | Simpler menu (only installed packs appear)               | **APPLIES**               | Filters `NAV_CONTRACT` by installed packs on top of DNA composition and `usePageLook`.                                                              |
| A8  | Trade-tailored onboarding (DNA → composition → packs)    | **APPLIES**               | `composeBusinessSolution` → `packsForPlan` maps business DNA directly to suggested packs with byte sizes.                                           |
| A9  | Clear module boundaries enforced by guard                | **APPLIES**               | `feature-packs.test.ts` ensures every route, nav item, sync entity, and engine belongs to one pack with acyclic `dependsOn`.                        |
| A10 | Measurable bundle budgets per pack in CI                 | **APPLIES**               | `scripts/packs/report.mjs` + `bundle-budgets.json` catch entry/pack regressions.                                                                    |
| A11 | Less server work (sync only installed entity types)      | **APPLIES**               | `sync_pull_changes_v2` filters `sync_change_log` by `p_entity_types` for `core` + installed packs.                                                  |
| A12 | Less DB work (fewer `hydrate` reads & smaller snapshots) | **APPLIES**               | Explicit `PULL_COLUMNS` (no `select('*')`) and entity-scoped pull/backfill eliminate unneeded table reads.                                          |

## 3. Key Risks & `NEEDS_OWNER_DECISION`

- **iOS `SHELL_HTML` asset packaging:** `apps/mobile/src/host/shell-webview.tsx` uses `file:///android_asset/shell/index.html` on Android and `Asset.fromModule(SHELL_HTML)` on iOS. Changing `singleFile: false` for Android must not break iOS's `copy-shell-for-ios.mjs` / `SHELL_HTML` fallback.
- **Native Ed25519 verification in mobile WebView:** WebCrypto Ed25519 support varies by Android WebView version; desktop main process has Node `crypto.verify`, while mobile adapter spike (`SPIKE-mobile-loader.md`) must verify runtime support on target Android APIs (`NEEDS_OWNER_DECISION` if a JS fallback dependency is ever needed).
- **`NEEDS_OWNER_DECISION` defaults applied (flags OFF):**
  - `packs.delivery = 'off'` (safe default)
  - `packs.installer = 'full'` (safe default)
  - Wi-Fi-only pack downloads = `true` by default
  - CDN bucket/domain, Ed25519 key pair, Play/Apple policy sign-off, and staging `EXPLAIN` remain owner actions.
