# حسابچه — بستن کامل پروفایل صنف (بدون «باقی‌مانده»)

این پرامپت جانشین همه‌ی «چه چیزی انجام نشد» در گزارش قبلی است. **تصمیم‌های مالک را همین‌جا گرفته‌ام؛ هیچ‌کدام را دوباره نپرس و هیچ‌کدام دلیل `BLOCKED` نیست.**
قاعده‌ی این دور: **پایان دور = صفر مورد باز.** اگر وسط کار چیزی گیر کرد، راه‌حل را خودت پیدا کن (پایین‌تر راه‌های جایگزین آمده). فقط دو چیز `BLOCKED_EXTERNAL_CREDENTIAL` مجاز است: اجرای SQL روی Supabase زنده، و چیزی که فیزیکی به دستگاه/حساب بیرونی نیاز دارد. هر چیز دیگر را تمام کن.

قیدهای ثابت: commit/push نکن · subagent نساز · DDL زنده نزن (migration فقط فایل در `docs/` + VERIFY) · هیچ موتور مالی دوم نساز · `any`/`@ts-ignore`/`eslint-disable` ممنوع · تغییرات تأییدشده‌ی قبلی (قرارداد فیلتر، `fetchProducts` از موتور، فیکس footer) را برنگردان · بیلد فقط بعد از سبز شدن همه‌ی سوئیت‌ها.

## کارهای اجباری (هر کدام با شرط «انجام‌شده»)

### ۱. B + E — موتور محلی و مهاجرت

- `local-schema.ts`: `business_types` + جدول/ستون‌های واحد، `SCHEMA_VERSION=8`، migration idempotent.
- `local-engine`: `GET/PATCH` صنف از دیتابیس دستگاه؛ کاهش موجودی با تبدیل واحد مشترک.
- **انجام‌شده وقتی:** تست migration روی کپی `hisabche.db` واقعی (v7→v8، دوبار اجرا، داده‌ی قبلی دست‌نخورده) + تست «۲ کارتن × ۲۴ = ۴۸ قطعه» **یکسان** در سرور (`fastify.inject` یا سرویس) و موتور محلی + تست دستگاه تازه (بدون sync) که صنف را generic نمی‌گیرد + golden vector جدید در `__golden__`.

### ۲. C — ویرایش صنف

- بخش «نوع کسب‌وکار» در `settings-page.tsx` (app-shell) **و** صفحه‌ی تنظیمات وب، از **یک کامپوننت مشترک** در `packages/ui`.
- ماتریس آفلاین (`offline-endpoint-matrix.ts`) ردیف دقیق بگیرد؛ `OfflineGate` غلط نشان ندهد.
- **انجام‌شده وقتی:** تست UI (رندر، تغییر، ذخیره)، تست HTTP، تست موتور محلی، و پس از ذخیره پروفایل/قابلیت‌ها/داشبورد بلافاصله عوض شود. کلیدهای i18n در سه زبان.

### ۳. D — ترتیب داشبورد

- تابع خالص `isCustomizedLook`، مصرف در داشبورد، تست دو حالت (با/بی رکورد pageLook) برای طلا و لیوان‌فروشی.

### ۴. A — توازن UI/سرور/موتور (قبلاً فقط «گزارش» شد، حالا ببند)

- باگ ثبت‌شده‌ی `local-engine/src/routes/invoices.ts:603-627` را **اصلاح کن** (بخش ۱ همین را پوشش می‌دهد) و تست موازی سه‌گانه: گردنبند ۱۵ g × ۳۳٬۰۰۰٬۰۰۰ = ۴۹۵٬۰۰۰٬۰۰۰ و لیوان ۱۲ × ۲۵٬۰۰۰ = ۳۰۰٬۰۰۰ در UI، سرور، موتور؛ همچنین `unitMismatch` در هر سه.

### ۵. موجودی/سند/بها — تأیید واقعی (قبلاً 🟡)

- PG محیطی بالا نمی‌آمد (`error code 1314`). به ترتیب امتحان کن تا یکی بالا بیاید: `TEMP/TMP → .pgtest/tmp` · اجرا با پوشه‌ی داده روی درایو مستقیم کاربر · بستن پروسه‌های postgres/initdb معلق · اجرای تک‌فایل با `--no-file-parallelism` · اگر باز هم نشد، با `embedded-postgres` و کاربر بدون ارتقا. **فقط پس از ثبت هر تلاش و خطایش** مجازی `ENV_BLOCKED` بنویس، و آن‌گاه معادل را با سرویس/ریپوی واقعی و دیتابیس in-process که موتور محلی دارد بسنج. فایل `invoice-write-document.pg.test.ts` باید ۲۰ اجرا شود نه skip، یا دلیل مستند + جایگزین اجراشده.

### ۸. بیلد و دیدن در برنامه‌ی واقعی (فقط بعد از سبز بودن ۷)

- `TEMP/TMP=.pgtest/tmp` · web build · Windows (`electron-builder --win -c.electronDist=node_modules/electron/dist`) · Android (`pnpm run android:release`، تاریخ APK را بسنج نه پیام Gradle را).
- برنامه‌ی Windows را باز کن (preview/computer-use): صنف را روی «طلافروشی» بگذار → گردنبند ۱۵ گرم → فاکتور آفلاین → جمع ۴۹۵٬۰۰۰٬۰۰۰؛ بعد «لیوان‌فروشی». اسکرین‌شات + لاگ.
- اگر دیدن زنده ممکن نبود، دلیل دقیق + وضعیت `IMPLEMENTED_NOT_LIVE_VERIFIED` فقط برای همان مورد.

## قانون پایان

گزارش فارسی با جدول و عددهای واقعی. **ستون «باقی‌مانده» باید خالی باشد.** هر ردیف یکی از: `VERIFIED_COMPLETE` · `IMPLEMENTED_NOT_LIVE_VERIFIED` (با دلیل دقیق و فرمانی که ناکام ماند) · `BLOCKED_EXTERNAL_CREDENTIAL`. نوشتن «پیاده نشد چون تصمیم لازم بود» ممنوع است — تصمیم‌ها بالا هستند. اگر تصمیمی را غلط می‌دانی، همچنان پیاده کن و در گزارش اعتراض مستند بنویس.

قبل از نوشتن گزارش، فهرست B، C، D، E، F، A و ۵ را یکی‌یکی با خروجی فرمان تیک بزن؛ گزارشی که یکی از آن‌ها را «انجام نشد» بنامد پذیرفته نیست و کار ادامه دارد.
