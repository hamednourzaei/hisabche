# Release gate — M7 is Production Verification, not development

> M7 builds no feature. It turns `IMPLEMENTED_NOT_LIVE_VERIFIED` into `VERIFIED_COMPLETE` by evidence only. Each step names who does it and what
> is recorded. A step that was not actually executed stays `NOT_VERIFIED`.

| #   | Step                                                                                                                                                                                                                            | Who                 | Evidence recorded                          |
| :-- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------------ | :----------------------------------------- |
| 1   | Compare the hash of each applied file with `M5-POST-APPLY-CHECKLIST.md`; read the version markers                                                                                                                               | Owner               | hash table                                 |
| 2   | Run `docs/PROBE-m5-state.sql`; send the table                                                                                                                                                                                   | Owner               | probe output                               |
| 3   | Apply the forward-fix and the fifth migration per `APPLY-RUNBOOK.md` (S2/S3)                                                                                                                                                    | Owner               | none (DDL success is not evidence)         |
| 4   | Run `docs/VERIFY-m5-combined.sql`; all 27 rows `pass = true`; send the table                                                                                                                                                    | Owner               | VERIFY output                              |
| 5   | Run `docs/FINDING-m5-post-apply.sql` block by block; healthy = no rows (block 8 informational)                                                                                                                                  | Owner               | block outputs                              |
| 6   | Take a snapshot                                                                                                                                                                                                                 | Owner               | —                                          |
| 7   | Create a disposable PostgreSQL; set `HISABCHE_TEST_PG_URL` and `HISABCHE_TEST_PG_DISPOSABLE=yes` in the process environment only                                                                                                | Owner / Environment | —                                          |
| 8   | Run all `*.pg.test.ts`, including `m5-real-postgres.pg.test.ts` (multi-connection races, real-role RLS, idempotency)                                                                                                            | Environment         | test output; until then `BLOCKED_EXTERNAL` |
| 9   | Deploy the backend AFTER the migrations, both switches OFF                                                                                                                                                                      | Owner               | deploy record                              |
| 10  | Staging smoke tests: package sale; delivery; return + restock; scrap (refused for a seller, accepted for a manager); offline sync (accepted + rejected); profit report with `basis = ledger`; package renewal; suspend / resume | Owner               | checklist per item                         |
| 11  | Physical runs on Web, Windows and Android; record which were executed                                                                                                                                                           | Owner               | per platform                               |
| 12  | Offline / online switching checks on a device                                                                                                                                                                                   | Owner               | —                                          |
| 13  | Owner and accountant decisions in `OWNER-DECISIONS.md` (B2-6, switches)                                                                                                                                                         | Owner + Accountant  | decisions                                  |
| 14  | Final go / no-go                                                                                                                                                                                                                | Owner               | signed record                              |

`VERIFIED_COMPLETE` for the database side requires: steps 1–5 with all rows `pass`; step 8 executed on a disposable real PostgreSQL; step 11 for
the platforms in scope. Until then the highest honest status is `IMPLEMENTED_NOT_LIVE_VERIFIED`.
