What that means

invoices really is the operational hub — it is the single most-queried table in the codebase. But it is not the root of the model.

workspace_id is. It appears on every tenant table and is the only security boundary. user_id records who acted and is never a filter — a manager must see an invoice a seller raised.

Organization scope — the wrapper around everything
workspaces→ workspace_members (role: owner|manager|seller)→ branches→ member_branches→ every tenant row
Empty branch assignment = UNRESTRICTED, not locked out. Settled decision: the alternative was that every existing member in every existing workspace lost access the day branch scoping shipped. Enforced by branchScopeFor(); a scoped member sees only their branches and not rows with no branch.

RLS helpers — SECURITY DEFINER

  • auth_workspace_ids()
  • is_workspace_member(ws, user)
  • auth_owned_workspace_ids()
Must stay SECURITY DEFINER. Without it the policy on workspace_members calls itself → 42P17.
Multi-table writes go through these, never through several client calls. A compensating DELETE after a partial failure is forbidden — it deletes rows a person may have edited in between. Errors are raised as SCREAMING_CASE codes (RAISE EXCEPTION 'POS_SESSION_NOT_OPEN') because the client parses them out of the message.

Authorization asks four questions, in order

1 · workspace→ 2 · capability→ 3 · branch→ 4 · record owner

  • 3 mayUseBranch(scope, branchId)

The two flows that define the product

Invoice → ledger (money)

customer→ products / price→ INVOICE→ tax freeze→ stock_movements + cost_layers→ payments + allocations→ journal_entries / journal_lines→ reports
Money is integer minor units everywhere; /100 only at the display edge. The tax rate is frozen onto the document so an offline invoice is not re-priced when it syncs.

Offline → sync → conflict

local write→ sync_mutations→ sync_change_log→ server→ sync_conflicts→ human decision
Only 5 entities sync: invoice · customer · product · transaction · time_entry. Budgets, dimensions, bank statements, exchange rates and fixed assets are deliberately outside — each reason recorded in offline-contract.test.ts.

invoice_id on time_entry is a billing lock the device may not write; on transaction the same field is allowed, because a payment taken at the counter knows which invoice it pays.
