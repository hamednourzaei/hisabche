# بازنشانی کامل دیتابیس — دو دستور

> ⛔ **این کار تمام داده‌های برنامه را پاک می‌کند و برگشت ندارد.**
> فقط وقتی که همه‌چیز داده‌ی تست است.

---

## پیش از هر چیز

**بکاپ بگیرید.** داشبورد Supabase → Database → Backups.

حتی وقتی مطمئنید داده‌ای نیست. یک بکاپی که لازم نشد، چند ثانیه وقت است؛
بکاپی که نگرفتید و لازم شد، پروژه است.

---

## قدم ۱ — پاک کردن

فایل: **`docs/_reset-drop-everything.sql`**

اسکریپت **مسلح نیست**. باید خودتان یک خط را عوض کنید:

```sql
v_armed boolean := FALSE;   -- ← به TRUE تغییر دهید
```

⚠️ این عمدی است. پیست‌کردن تصادفی فایل، یا اجرا روی پروژه‌ی اشتباه چون دو تب
SQL Editor شبیه هم‌اند، **هیچ کاری نمی‌کند** مگر اینکه آگاهانه مسلحش کنید.

بعد کل فایل را در SQL Editor بزنید.

### چه چیزی می‌رود و چه چیزی می‌ماند

| می‌رود                          | می‌ماند                         |
| ------------------------------- | ------------------------------- |
| هر جدول، ویو و تابع در `public` | `auth.*` — حساب‌های کاربری      |
| policyها، triggerها، indexها    | `storage.*` — فایل‌های آپلودشده |
| typeهای سفارشی                  | همه‌ی schemaهای خود Supabase    |

**ورودهای شما باقی می‌مانند.** بعد از ساخت دوباره، با همان حساب وارد می‌شوید و
یک کارگاه خالی می‌بینید.

### چرا جدول‌ها را کشف می‌کند به‌جای اینکه فهرست کند

فهرست دستیِ `DROP` همان لحظه‌ای که یک migration جدول اضافه کند غلط می‌شود — و
خرابیِ آن **ساکت** است: جدول فراموش‌شده با شکل قدیمی و policy قدیمی‌اش زنده
می‌ماند و ساخت دوباره‌ی «تمیز» در سکوت تمیز نیست.

اسکریپت `information_schema` را می‌خواند، پس همان چیزی را پاک می‌کند که واقعاً
هست.

### خروجی را بخوانید

قبل از پاک‌کردن، تعداد سطر هر جدول را `RAISE NOTICE` می‌کند. اگر عددی دیدید که
انتظارش را نداشتید، **همان‌جا لغو کنید** — این آخرین لحظه‌ای است که لغو‌کردن
فایده دارد.

آخرش این را برمی‌گرداند:

```
tables_left | views_left | functions_left | auth_users_kept
     0      |      0     |       0        |       <کاربران شما>
```

⚠️ `auth_users_kept` تنها عددی است که **نباید صفر باشد**. اگر صفر بود، اسکریپت
به schemaیی رسیده که نباید — بکاپ را برگردانید، روی این نسازید.

## قدم ۲ — ساخت دوباره

```bash
node scripts/bundle-migrations.mjs
```

فایل: **`docs/_bundle.sql`** — ۳۳ migration، حدود ۲۷۰ کیلوبایت، ۵۷ `CREATE
TABLE` و ۴۷ `CREATE POLICY`.

کل فایل را در SQL Editor بزنید.

### ترتیب اهمیت دارد و درست است

سه چیزی که در این ترتیب load-bearing است:

- `live-reconciliation-migration.sql` **اول** — چون `exchange_rates` را می‌سازد
  که فایل بعدی ALTER می‌کند
- توابع `SECURITY DEFINER` در خط ۵۳۰۳ ساخته می‌شوند، و
  `workspace-members-rls-migration.sql` در خط ۵۸۹۸ از آن‌ها استفاده می‌کند —
  یعنی تابع قبل از مصرف‌کننده‌اش هست ✓
- `schema-drift-fix-migration.sql` بعد از هر `CREATE TABLE` که ALTER می‌کند

⚠️ فایل **idempotent** است: `IF NOT EXISTS` همه‌جا، و `DROP POLICY IF EXISTS`
قبل از هر `CREATE POLICY`. دوباره زدنش چیزی خراب نمی‌کند.

---

## قدم ۳ — اثبات

دو فایل، به همین ترتیب:

```
docs/_verify-after.sql    → ۸ بررسی، هرکدام با حکم خودش
docs/_verify-rls.sql      → RLS واقعی با نقش authenticated
```

⚠️ `_verify-rls.sql` مهم‌تر است. `_verify-after` می‌گوید policy **وجود دارد**؛
`_verify-rls` می‌گوید policy **کار می‌کند** — با یک کاربر واقعی، و نشان می‌دهد
که نشت بین‌مستأجری صفر است.

بین قدم ۱ و ۲ برنامه خراب است. آن دو یک عملیات‌اند، نه دو تا.

## اگر چیزی اشتباه رفت

| علامت                          | معنی                                               | کار                                                      |
| ------------------------------ | -------------------------------------------------- | -------------------------------------------------------- |
| `42P17 infinite recursion`     | policyی روی `workspace_members` خودش را صدا می‌زند | `rls-recursion-fix-migration.sql` را دوباره بزنید        |
| `42703 column does not exist`  | bundle ناقص اجرا شده                               | کل bundle را دوباره بزنید — idempotent است               |
| `tables_left > 0` بعد از قدم ۱ | چیزی پاک نشده                                      | نامش را از خروجی بردارید و دستی `DROP TABLE ... CASCADE` |
| `auth_users_kept = 0`          | اسکریپت به `auth` رسیده                            | **بکاپ را برگردانید**                                    |

## چرا دستیار خودش اجرا نمی‌کند

تصمیم ثبت‌شده‌ی پروژه: **DDL روی دفتر مالی، تصمیمی است که اسم یک آدم پایش
می‌خورد.** اسکریپت را من می‌نویسم؛ دکمه را شما می‌زنید.
