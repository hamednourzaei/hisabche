## 2. روش و قاعده‌ی شاهد

۱. ابتدا `git status` (پاک بود) و HEAD ثبت شد (`AUDIT-BASELINE.md`).
۲. دو اسکریپت فقط‌خواندنی و تکرارپذیر در مخزن اضافه شد: `scripts/audit/capability-gap-scan.mjs` (کلیدواژه‌ی ۵۰ شکاف روی ۳٬۱۷۹ فایل کد/SQL) و `scripts/audit/universal-core-orphans.mjs` (مصرف‌کننده‌ی هر export دامنه). خروجی اسکن «سرنخ» است، نه اثبات؛ هر ادعای مهم با خواندن فایل تأیید شد.
۳. هر ردیف سه محور مستقل دارد: Implementation (MISSING / PARTIAL / IMPLEMENTED)، Verification (UNVERIFIED / PARTIALLY_VERIFIED / VERIFIED / N/A / BLOCKED_EXTERNAL)، Architecture (CORRECT / WRONG_LAYER / DUPLICATED / NEEDS_REFACTOR / MISSING).
۴. **تعریف «پیاده‌شده»**: یک قاعده‌ی خالص با تست، پیاده‌سازی قابلیت نیست؛ قابلیت وقتی IMPLEMENTED است که از route/job/UI به آن برسیم. تابعی که فقط تست صدایش می‌زند: `ORPHAN` (قاعده‌ی «وجود دارد و هیچ‌کس صدایش نمی‌زند»، CLAUDE.md §۷٫۱).
۵. PostgreSQL واقعی روی این دستگاه اجرا نمی‌شود: ۹۴ فایل `*.pg.test.ts` در `backend/src/__tests__` (از ۴۵۶ فایل تست) اجرانشدنی‌اند → هر ادعای وابسته به آن‌ها `BLOCKED_EXTERNAL`، نه `VERIFIED`.
