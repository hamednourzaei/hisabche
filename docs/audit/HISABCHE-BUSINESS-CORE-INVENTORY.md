## 2. Cross-core observations

- **FACT** Invoice create is a sequence, not one transaction: `invoice_write_document` RPC (`services/invoice.service.ts:2669`), then tax (`:1322-1334`, failure leaves the invoice with `tax_status='failed'`), then shelving/costing, then ledger; ledger failure rethrows (`:1395-1398`) after the invoice and stock already exist. Recovery is a manual route `POST /api/invoices/post-unposted` (`routes/invoice.routes.ts:322`). INFERENCE: a client that sees 500 may retry; idempotency keys mitigate duplicates, but the "invoice saved, ledger missing" state is reachable.
- **FACT** 10 modules are registered as WRITTEN_NOT_WIRED (`backend/src/__tests__/unwired-capability.test.ts`, 20 WIRED / 10 WRITTEN_NOT_WIRED entries).
- **FACT** Duplicate rules kept beside their replacement: `services/accounting.service.ts` vs `services/accounting/`; `services/webhook.service.ts` vs `services/developer/`; `services/checkout.service.ts` vs subscription orders + wallet.
- **FACT** `node scripts/audit-unwired-routes.mjs` (exit 0): 857 routes, 661 client path strings, **122 routes with no client caller**. Some are legitimately external (OAuth token, public token pages, updater, sync stream built dynamically) — the list over-reports; see `HISABCHE-DEPENDENCY-MAP.md` §4.
