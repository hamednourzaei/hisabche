## 2. برش ۱ — فروشگاه

`Business Profile → GOODS_RETAIL → Inventory → Sales → Purchase → Payment → Dashboard → Navigation → Terminology`
موتورهای لازم همه IMPLEMENTED‌اند (`General retail: SUPPORTED`). آنچه کم است: ترکیب Navigation و Terminology (امروز `recommendedModules` مصرف‌کننده ندارد)، policy، و اتصال واریانت اگر فروشگاه لباس/کفش است.

## 3. برش ۲ — معلم

`Business Profile → SERVICE → Appointment → Package Credit → Payment → Receivable → Dashboard → Navigation → Terminology`
Package credit/تحویل خدمت/پرداخت/دریافتنی IMPLEMENTED‌اند. کم است: زمان‌بندی (آنلاین‌-فقط؛ قاعده‌ی تعارض بی‌مصرف و قید پایگاه‌داده) و ترکیب.

## 4. معیارهای پذیرش (۱۵ مورد)

۱. هر دو برش از یک هسته‌ی جهانی استفاده می‌کنند. ۲. هیچ هسته‌ی صنفی ساخته نمی‌شود. ۳. هیچ موتور مالی صنفی نیست. ۴. هیچ موتور موجودی صنفی نیست. ۵. هیچ `if (industry === …)` اضافه نمی‌شود (امروز صفر است؛ گارد). ۶. موتور مالی موجود مرجع می‌ماند. ۷. موتور موجودی موجود مرجع می‌ماند. ۸. آفلاین همان قاعده‌ها را اجرا می‌کند. ۹. مجوز یکدست. ۱۰. sync یکدست. ۱۱. واژگان از ترکیب می‌آید. ۱۲. داشبورد/منو از ترکیب می‌آید. ۱۳. برچسب پشتیبانی صادق است (فقط از قواعد `INDUSTRY-CAPABILITY-MATRIX.md`). ۱۴. تست‌ها گردش واقعی را اثبات می‌کنند (نه فقط قاعده‌ی خالص). ۱۵. ترکیب جعلی فقط-UI وجود ندارد.
