## 2. Findings

### 2.1 Anonymous "buy first" order path is unreachable — Medium

FACT: `POST /api/billing/orders` handles an optional token itself and says it proceeds "as anonymous Path A" (`routes/billing.routes.ts:918-931`). The global hook authenticates every path not in `publicPaths`/`exactPublicPaths` (`backend/src/index.ts:353-410`); `/api/billing/orders` is in neither (only `/api/billing/plans` is). INFERENCE: an anonymous call gets 401 before the handler; Path A cannot start. The handler also returns raw `err.message` to the client (`:938-942`).

### 2.2 Order ownership check skips orders with no creator — Medium

FACT: `provisionFromOrder` rejects only when `order.created_by_user_id && order.created_by_user_id !== userId` (`services/subscription-order.service.ts:246`). An order created while `getUser` failed (`routes/billing.routes.ts:928-930` swallows the error) has `created_by_user_id = null` (`subscription-order.service.ts:102`) and can be provisioned by **any** signed-in user who holds the order id, without the claim token. Mitigation: ids are UUIDs and orders must be `paid` first (`:261`).

### 2.3 Offline licence trust is first-use — High (licensing integrity), NEEDS_OWNER_DECISION

FACT: the device verifies with the build key `VITE_OFFLINE_LICENSE_PUBLIC_KEY` if set (`packages/app-shell/src/shared/lib/api.ts:23-24`), else with a key kept in device storage, else fetches `/public/offline/licence-key` and stores it (`offline-license.ts:89-109`). No committed build config sets the variable (`grep` finds only the generator `scripts/generate-offline-licence-keys.mjs:28`). INFERENCE: on a build without the env var, whoever can write the device's storage can plant their own public key and sign their own licence. Separately, the server **private** key is generated at runtime and stored as `private_key_hex` in `offline_license_signing_keys` (`backend/src/services/offline-license.service.ts:250-256`): anyone with service-role DB read can forge licences.

### 2.4 Two different "current subscription" rules — Medium, NEEDS_OWNER_DECISION

FACT: `getCurrentSubscription` (what `/billing` shows) falls back from the workspace row to the acting **user's** first subscription row (`services/billing.service.ts:265-272`) and auto-creates a trial on read (`:344-346`). The write lock uses `getWorkspaceAccess`, which resolves via the workspace or its owner and treats "no row" as not expired (`:366-389`). INFERENCE: in a second workspace without its own row, the billing page can show another workspace's plan while the lock applies a different rule; a workspace with no subscription row is never locked (fail-open by design, `:148-152`).

### 2.5 Subscription cache is per process

FACT: access is cached 60 s and the subscription 300 s in `memoryCache` (`:356,393`). INFERENCE: with more than one backend instance, a renewal flush on one instance does not reach the others for up to 5 minutes.

## 3. Recommendations

1. Decide Path A: add `/api/billing/orders` to `exactPublicPaths` with its own rate limit, or delete the anonymous branch.
2. Require claim token when `created_by_user_id` is null.
3. Set `VITE_OFFLINE_LICENSE_PUBLIC_KEY` in Windows and Android build configs, fail closed without it; move the private key to a KMS/secret.
4. Implement trial/renewal emails through `email-outbox.ts`; remove the `users` table read.
5. Remove the dead `/api/auth/verify-email` allow-list entry or implement it.
