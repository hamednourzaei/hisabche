# Capability model gap matrix

Date: 2026-10-26. Input: `generated/write-route-authz.json` (416 write routes), the 74 routes that showed no route-level, handler-level or service-level check, and the reading in `security-tenant-trace.md`. **Nothing is recommended for blanket application: each family below is classified on its own.** Decisions marked `NEEDS_PRODUCT_DECISION` belong to the owner.

## 0. How authorization works today (facts)

## 3. Families gated by an inline role floor (not capabilities)

`attendance` (sheet, shifts, assignments), `attendance-device`, `attendance-link`, `campaigns`, `snapshots`, `escalation` use `requireRole(request.tenancy, 'manager')` (and `'owner'` in places). They are `ROLE_ONLY_ACCEPTABLE` today; the only product question is whether they should move to named capabilities so a custom role can grant them.

## 4. Counts and what they mean

Of the 74 routes that first looked unguarded: **10** capability-exists-not-applied rows (§1), **4** cross-tenant routes (N-18: 2, N-31: 2) that also lack any authorization, **~45** in §2 families, **~6** safe, **3** AI model-call routes undecided. The blanket "114 routes" is retired.
