# N-30 — `POST /api/sync/push` with `operation: delete`

Date: 2026-10-26. Evidence kinds: **CODE** (file:line read), **TEST** (existing test run), **SQL** (static reading of `docs/*.sql`, parsed by `scripts/audit/fk-dependents.mjs` → `generated/fk-dependents.json`). **Not executed against a database.** Nothing was changed.

## Verdict

**`CONFIRMED_P0` for the road; the damage per entity is graded below.** The route lets any workspace member delete rows of nine entity types with no capability, no domain rule, no ledger or stock reversal, no audit entry. Whether a given delete _succeeds_ depends on foreign keys that are `NOT VALID` or absent in the SQL files and whose live state is unknown (`LIVE_UNVERIFIED`). Rows without dependants (payments-like `transactions`, `time_entries`, `exchange_rates`, `warehouse_stock`, unused masters) are deletable by construction.

## 2. Comparison with the domain delete (`DELETE /api/invoices/:id`)

`invoice.routes.ts:444-447` requires `invoice.delete` (owner); `InvoiceService.delete` (`invoice.service.ts:1649-1703`) additionally: `scopes.assertMay` (branch/creator), `sod.assertAllowed`, `sod.recordAction`, `reverseEffects` (ledger reversal, own payments, stock, cost layers), removal of `invoice_tax_lines`, `invoice_installments`, `invoice_items`, then the header, then `logBusinessEvent`. The sync road does none of this.

## 6. Who sends deletes today

Neither client: desktop `routeFor` sends every delete to the domain route (`push-routing.ts:100-102`), and `pushVersioned` is the only caller of `/sync/push` (`sync-engine.ts:642`, `sync-runner.ts:109`). A direct HTTP call, a modified client or a leaked token can.

## 7. A related finding discovered while tracing (N-44)

Both real clients post `{ mutations: [...] }` to `/sync/push` **without `deviceId` and `batchId`**, which `syncPushRequestSchema` requires. Probe: `scripts/audit/probe/sync-push-schema.test.ts` run with vitest → `success = false {"deviceId":["Required"],"batchId":["Required"]}`; the same body plus the two fields → `true`. `rg batchId` finds no client that sets it. Consequence (code-level, not run end-to-end): every versioned push from desktop and mobile is answered `400 invalid_push_batch`; the optimistic-concurrency and conflict-filing path described in `GATE-08-sync.md` is unreachable from the shipped clients. The delete road above stays reachable to anyone who sends a correct body.
