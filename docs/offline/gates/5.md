## 3. Defects Discovered in Product Code & Resolved

In accordance with Section 0.5 Rule 3 of `docs/offline/OFFLINE-EDITION-PROMPT.md` («_C never fixes; C reports. A failing test goes into `docs/offline/gates/<phase>.md` with the command, the output and the file it points at. The owner of that file fixes it. C re-runs._»), the verifier reported two defects identified in `@hisabche/local-engine` (owned by Agent A). Both were promptly fixed by Agent A and re-verified green by Agent C:

### Defect 1: Customer Ledger Movement Kind Mismatch (RESOLVED)

- **File:** `packages/local-engine/src/routes/customers.ts`, line 297.
- **Defect Description:**
  In `GET /customers/:id/balance`, invoice movements were mapped with:
  `kind: (inv.type === 'sale' ? 'invoice_sale' : 'invoice_purchase') as LedgerMovement['kind']`
  However, `LedgerMovement['kind']` in `@hisabche/validation` (`packages/validation/src/schemas/payments.domain.ts`) is typed as `'sale' | 'purchase' | 'payment_in' | 'payment_out' | 'return'`.
  Because `kind` was passed as `'invoice_sale'`, the `switch (movement.kind)` in `partyBalance()` failed to match any branch and discarded the sale amount. Customer balance then subtracted receipts from 0, producing a negative balance (-21,000 AFN) when it should be settled at 0 AFN.
- **Resolution (Agent A):**
  Changed line 297 to:
  `kind: (inv.type === 'sale' ? 'sale' : 'purchase')`
  Verified by Step 14 in `gate-5-transport.test.ts`: **PASS**.

### Defect 2: Invoice Cancellation Reverses Stock Across All Warehouses (RESOLVED)

- **File:** `packages/local-engine/src/routes/invoices.ts`, lines 829–834.
- **Defect Description:**
  In `POST /invoices/:id/cancel`, product stock reversal executed without scoping to the invoice warehouse:
  ```sql
  UPDATE product_stock SET qty = qty + ?, updated_at = ?
  WHERE workspace_id = ? AND product_id = ? AND deleted_at IS NULL
  ```
  Because the query did not filter by `warehouse_id`, cancelling a sale added stock to **every warehouse** that held that product in the workspace. In a multi-warehouse setup (e.g. Kabul warehouse with 115 units, Herat warehouse with 15 units), cancelling a sale from Kabul incorrectly incremented Herat warehouse stock to 20 units.
- **Resolution (Agent A):**
  Looked up `assignedWarehouse` from `cost_consumption` (for sales) or `cost_layer` (for purchases) and added `AND warehouse_id = ?` to the `UPDATE product_stock` query.
  Verified by Step 15 in `gate-5-transport.test.ts`: **PASS**.
