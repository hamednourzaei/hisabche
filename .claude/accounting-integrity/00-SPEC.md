# یکپارچگی حسابداری — «نامعلوم، صفر نیست» (۱۱ اکتبر ۲۰۲۶)

> ریشه: فاکتور `INV-000077` — ۱۵ عدد × ۳۰٬۰۰۰، روی کالایی که قیمت خرید داشت، نشان می‌داد
> «بهای تمام‌شده ۰ · سود ۴۵۰٬۰۰۰ · حاشیه ۱۰۰٪». و تراز آزمایشی مانده‌ی صندوق را «−۱۰٬۲۲۰٬۰۰۰» می‌نوشت.

وضعیت این سند: `IMPLEMENTED_NOT_LIVE_VERIFIED`. هیچ migration تازه‌ای لازم نشد.

---

## ۱. حکم ممیزی COGS

**`DEFECT — COGS NOT CALCULATED`** (و در پیِ آن `DEFECT — UI`).

| پرسش | پاسخ، با نشانی |
|---|---|
| «بها = ۰» از کجا آمد؟ | لایه‌ی بها (`cost_layers`) فقط از دو جا نوشته می‌شد: فاکتور خرید (`invoice.service.ts#applyCosting`) و دریافت سفارش خرید (`purchasing.service.ts`). **ساختن کالا با موجودی و قیمت خرید هیچ لایه‌ای نمی‌ساخت.** |
| فروش چه کرد؟ | `inventory_consume_layers` با سیاست پیش‌فرض `block` خطای `INVENTORY_INSUFFICIENT_STOCK` داد؛ `applyCosting` آن خط را در `uncosted` گذاشت و رد شد. هیچ `cost_consumptions` ای نوشته نشد. |
| سند `JV-…` چه دارد؟ | فقط «دریافتنی / فروش». خط «بهای تمام‌شده / موجودی» فقط وقتی نوشته می‌شود که `cost > 0` (`createAccountingEntries`). |
| UI چه کرد؟ | `buildProfitReport` نبودِ consumption را `cost: 0, costMissing: true` برمی‌گرداند و `profit = revenue − 0`. پنل یک هشدار می‌گذاشت و **همان عدد را نشان می‌داد**. |
| FIFO/AVCO اجرا می‌شود؟ | بله، داخل Postgres — وقتی لایه‌ای باشد. |
| انبار؟ | خط‌های فاکتور `warehouseId` ندارند ⇒ مصرف با انبارِ `null` است و از همه‌ی لایه‌های کالا می‌خورد. بهای تمام‌شده **در عمل به تفکیک انبار نیست**. |

### چرا تست‌ها ندیدند

1. همه‌ی تست‌های بها با **فاکتور خرید** شروع می‌شدند، پس لایه همیشه بود. مسیر واقعیِ یک دکان («کالا را با موجودی بساز، بفروش») fixture نداشت.
2. تنها تستی که به «بدون بها» می‌رسید `toMatchObject({ cost: 0, costMissing: true })` بود — **صفر را قفل می‌کرد** و به سود و حاشیه‌ی ساخته‌شده روی آن نگاه نمی‌کرد.

الگو: **پرچم هشدار را سنجیدیم، نه عددی که آدم می‌خواند.**

## ۳. مصرف‌کننده‌های سود — همه بازبینی شدند

| جا | قبل | بعد |
|---|---|---|
| پنل «این سود از کجا آمده؟» | بها ۰، سود = فروش، ۱۰۰٪ | «نامشخص / قابل محاسبه نیست» + دکمه‌ی ثبت بها |
| جدول سود کالاها + جمع‌ها | سود = فروش | «قابل محاسبه نیست» + «سودِ فروش‌های دارای بها» + «فروشِ بدون بها» |
| کارت سود هر ارز | عدد | «قابل محاسبه نیست» |
| صندوق (حاشیه‌ی هر تراکنش) | از قبل `null` می‌شد | بدون تغییر |
| سفر پول کالا | `profit ?? 0` | `null` ⇒ «قابل محاسبه نیست» |
| نقطه‌ی سربه‌سر | `contribution = revenue` ⇒ تعداد سربه‌سرِ خیلی کم | `COST_UNKNOWN`، بدون عدد |
| سناریوی «اگر…» | روی سود غلط | `meaningful: false` با دلیل |
| مقایسه با هم‌ترازها | حاشیه‌ی غلط منتشر می‌شد | `null` |
| سرمایه در گردش (DIO/CCC) | از بهای ناقص | `null` + `costOfGoodsSoldKnown` |
| خلاصه‌ی دوره (insights، AI) | **فرمول دوم**: جمع `invoices.total` (با مالیات، همه‌ی ارزها با هم) − همه‌ی consumptionها | از همان `getProfitReport` به ارز دفاتر؛ سود `null` وقتی بها ناقص است |

گارد الگو: هر `profit|marginPercent|contribution` با `?? 0` یا `|| 0` در UI، API، app-shell و بک‌اند قرمز می‌شود
(`packages/ui/src/__tests__/unknown-is-not-zero.test.ts`).
