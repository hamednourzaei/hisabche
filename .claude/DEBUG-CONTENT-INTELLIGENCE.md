## CI-001 — 🔴 کپی «��simplify» یک URL builder، outage برمی‌گرداند

**علامت:** `ai-provider-endpoint.test.ts` قرمز شد:

```
expected 'https://openrouter.ai/api/v1/chat/com…'
     to be 'https://openrouter.ai/api/v1/chat/com…'
```

**ریشه:** `providerEndpoint` را به `provider-client.ts` کپی کردم و **سه خطش را نوشتم**:

```ts
const base = (baseUrl?.trim() || fallback).replace(/\/+$/, '')
return `${base}${path}` // ❌
```

نسخه‌ی واقعی چهار خط بیشتر دارد:

```ts
if (base.endsWith(path)) return base // base خودش endpoint کامل است
const root = /\/v1$/.test(base) ? base : `${base}/v1`
return `${root}${path}` // ✅
```

**چرا این مهم است:** آن دو خط یک باگ **تاریخی** را نجات داده بودند. کامنتش
می‌گوید «OpenRouter's docs این را اول نشان می‌دهد، و همه همان را paste
می‌کنند» — یعنی `https://openrouter.ai/api/v1/chat/completions` مستقیم. بدون
`endsWith`، این می‌شد `.../v1/v1/chat/completions` و **همه‌ی gateway‌ها** می‌شکستند.

> **درس:** «کپی ساده‌ترِ یک تابع، تغییر رفتار نیست.»
> اول نسخه‌ی کامل را بخوان، **بعد** بنویس. اگر نسخه‌ی ساده‌تر از نسخه‌ی
> واقعی کوتاه‌تر است، احتمالاً چیزی را حذف کرده‌ای که لازم بوده.
> و: اگر یک تابع سه شاخه دارد، «سه خط» نمی‌شود.

## CI-002 — 🔴 چرخه‌ی ماژول، و راه‌حل غلط

**علامت:** `no-service-import-cycles.test.ts` قرمز شد.

**ریشه:** `provider-client` → `ai-chat.service` (برای `providerEndpoint`) و
`ai-chat.service` → `provider-client` (برای `callProvider`). ⭕

**راه‌حل اول — غلط:** بردم `providerEndpoint` به یک فایل leaf. نتیجه:
`ai-provider-endpoint.test.ts` شکست، چون خودش
`providerEndpoint` را از `ai-chat.service` import می‌کند.

**راه‌حل درست:** `providerEndpoint` **سر جایش ماند** و فقط منطق fetch جابه‌جا شد.
دو چیز مستقل‌اند:

- **endpoint**: ساخت URL — توابع محض، جایش امن است
- **fetch**: رفتار شبکه — لایه‌ای که pipeline به آن نیاز دارد

> **درس:** وقتی یک guard می‌گوید «این در این فایل باشد»، جابه‌جا کردنش یعنی تغییر
> قرارداد، نه تمیزکاری. اول بپرس **چرا** آنجا نشسته، بعد تصمیم بگیر.

## CI-003 — 🟡 guard را شل نکردم، **قوی‌ترش** کردم

`ai-provider-boundary.test.ts` می‌گفت:

```ts
expect(chat.match(/response\.text\(\)/g)).toHaveLength(1)
```

⚠️ وسوسه این بود که بنویسم `toBeLessThanOrEqual(1)` یا کلاً حذفش کنم تا سبز شود.
**این همان کاری است که در `EXECUTION.md` §۳ ممنوع است.**

آنچه کردم: شمارش از **یک فایل** به **کل ماژول** رفت.

```ts
const wholeModule = ['ai-chat.service.ts', 'provider-client.ts', 'reporting-reader.ts']
  .map((f) => code(join(AI, f)))
  .join('\n')
expect(wholeModule.match(/response\.text\(\)/g) ?? []).toHaveLength(1)
```

قبلاً یک فایل می‌توانست بدنه‌ی provider را بخواند. حالا هم یک فایل می‌خواند. **و
ماژول سومی که `response.text()` اضافه کند، همچنان قرمز می‌شود.** سخت‌گیری
حفظ شد، فقط دامنه‌اش با معماری جدید هماهنگ شد.

> **درس:** «تست قرمز شد» یعنی معماری عوض شده، نه اینکه تست بد است. اول بپرس
> **کدام‌یک** قدیمی است.

### CI-005 — 🟡 تستی که روی ستون‌بندی SQL قرمز شد

**علامت:**

```
expected '…' to contain 'ALTER TABLE public.blog_content_brief…'
```

**ریشه:** SQL ستون‌بندی هم‌تراز دارد
(`ALTER TABLE public.blog_content_briefs␣␣ENABLE …`) و تست رشته‌ی دقیق
می‌خواست.

**راه‌حل:** تست را **نسبت به فاصله بی‌حساس** کردم، نه اینکه ستون‌بندی SQL را
عوض کنم.

> ⚠️ **این سومین بار است** که یک assertion شکسته را با «اصلاح ظاهری» می‌پوشانم
> و بار بعد می‌شود محتوای واقعیِ آن تست از بین برود. الگوی درست:
> **تستی که روی چیدمان حساس است، اول از همه می‌شکند و بعد غیرفعال می‌شود.**

### تصمیم‌های امنیتی این فاز

| تصمیم                                            | چرا                                                                                                                                             |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **RLS روشن، بدون policy**                        | RLS + بدون policy = همه‌چیز denied. backend با `service_role` دور می‌زند. یک policy اینجا **هیچ سودی ندارد** و فقط ریسک نشت brief منتشرنشده است |
| `REVOKE` صریح برای `PUBLIC, anon, authenticated` | تا اضافه‌شدن policy بعدی «بی‌خطر» به‌نظر نرسد                                                                                                   |
| `competitor` مقدار معتبر                         | رقیب **ورودی پژوهش** است. پنهان‌کردنش ورودی را نام看不见 می‌کند. ممنوعیتِ کپی در originality gate است، نه در schema                             |
| `claim` nullable                                 | خیلی از منابع پشتِ کل مقاله‌اند نه یک جمله. `NOT NULL` باعث می‌شود آدم متن الکی بنویسد                                                          |
| `run_key` با `UNIQUE`                            | دابل‌کلیک = یک run، نه دو run و دو فاکتور Tavily                                                                                                |
| `url_normalised` با `UNIQUE`                     | یک منبع با `http`/`https`/`www` سه بار برمی‌گردد. سه سطر = یک منبع که سه بار سایت شده                                                           |

⚠️ و نرمال‌سازی URL **در repository** است نه در SQL — چون Postgres
canonicaliser قابل‌حمل ندارد و نیمه‌درستِ SQL یک منبع دائمیِ تکراری است.
